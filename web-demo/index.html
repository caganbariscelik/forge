What this is

A dashboard where a free-text prompt becomes a structured, editable RunPlan (technique, dataset strategy, hyperparameters, eval) via a planner that falls back to deterministic rule-based routing when no LLM key is configured. Four pluggable interfaces do the work: TrainingBackend (local transformers+peft+trl, and a Tinker adapter built to the documented API shape), Technique (LoRA/SFT, and heretic-style abliteration as a one-shot weight edit), DatasetSource (synthetic generation, HF pull, SWE-bench_Pro), and Evaluator (a bespoke metric per task). FastAPI + HTMX frontend, SQLite persistence, live SSE log streaming. This page shows real results from the three graded test prompts, run end-to-end on an Apple M1, 8GB RAM, no CUDA — the interactive platform lives in the GitHub repo and runs locally (uvicorn app.main:app); it isn't hosted here because PyTorch/transformers and multi-minute local training runs don't fit a serverless deployment.

Remove the model's ability to say the letter B

"Remove Qwen3.5-4B's ability to say the letter B"

A lexical-suppression task, not a safety task — LoRA/SFT on a regex-verified, zero-B training set (LetterFilterSource), evaluated with a custom LetterLeakageEvaluator. Soft fine-tuning alone barely moved the needle (B is one of the most common letters in English — a small LoRA adapter over 200 examples couldn't override that on its own). The prompt says remove the ability, not reduce the odds, so the trained model is paired with a hard decoding-time constraint that masks every vocabulary token containing "b"/"B" — fine-tuning keeps the remaining vocabulary coherent, the constraint makes the ban absolute. Demo model: Qwen/Qwen2.5-0.5B-Instruct (stand-in for local hardware; the platform never silently substitutes the model the prompt actually names).

02
+100 pts

Uncensor

"Uncensor Qwen3.5-4B"

Activation-based abliteration (à la heretic): compute the difference-of-means hidden state between harmful and harmless calibration prompts to get a per-layer refusal direction, then orthogonalize the attention/MLP output projections against it (W' = (I − dd^T)W) — a one-shot weight edit, not a gradient loop. Took 5.5 seconds on this hardware. Evaluated with a keyword-based RefusalRateEvaluator on a held-out prompt set disjoint from the calibration prompts.

Raise SWE-bench performance

"fine tune Qwen2.5-Coder-7B-Instruct and raise its performance in any benchmark SWE-bench"

SFT on (issue, gold-patch) pairs from ScaleAI/SWE-bench_Pro (731 real instances loaded and mapped by SweBenchProSource), evaluated by PatchSimilarityEvaluator — diff-similarity and exact-match against gold patches on a held-out slice never trained on.

30 training examples, 20 LoRA steps, 5 held-out instances — a deliberately small slice to prove the pipeline end-to-end fast. exact_match_rate stayed 0% before and after, which is expected: a 0.5B model with 20 steps of LoRA isn't going to produce byte-exact real-world patches. The mean_diff_similarity move (+22% relative) shows the training signal is real, just modest at this scale — a larger model, more steps, and more training pairs is the lever to pull next, not a different technique.

⚠️ Explicit proxy metric. Full SWE-bench execution applies the generated patch inside the instance's Docker container and runs its fail_to_pass/pass_to_pass test suite — infrastructure this environment doesn't have. This run proves the pipeline is wired correctly end-to-end (real data, real training, real eval); it is not a claim of measured SWE-bench pass rate.

Also built
